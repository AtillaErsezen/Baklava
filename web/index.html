What happens between upload and download

Numbers from a recorded run on churn.csv: 3,000 rows, 9 features, target Churn.

  1. Upload

    The server profiles every column and suggests a target. Before anything else runs, 600 rows (20%) go into a locked hidden set.

  2. 33 checks

    Leakage, ID columns, missing values, outliers, imbalance and drift. Here the checks flagged refund_issued, which is only filled after a customer leaves.

  3. Sample size n*

    A Hoeffding bound says how many rows a fair comparison needs. Early rounds use 500 rows, so weak pipelines drop out cheaply.

  4. Race

    3,000 pipelines generated, the 243 most promising raced. Each rung triples the rows and keeps a third; paired tests cut the ones that are clearly worse.

  5. Confirm

    The top 3 run 10 paired folds. A corrected t-test and a Bayesian check decide which gaps are real.

  6. Hidden test

    The pick is scored once on the 600 locked rows. Nothing gets tuned after that.

  7. Your model

    You download the fitted model, its parameters, a model card and a Python script that retrains it on new data.
